# Software Engineer Resume Template

> **Format:** Markdown (`.md`) · **Designed for:** Humans + AI agents

*For engineers building and shipping software as an individual contributor, from early-career through mid-level.*

Software engineer resumes are judged on evidence that you can independently design, build, and ship working software — and that your code holds up once it's in front of real users or real load. Hiring managers skim for concrete outcomes, not tool lists, so this template centers each bullet on a problem you solved and a result you can defend in an interview. Use it as a starting skeleton, then swap in your own numbers and systems.

## Resume Structure

1. **Header** — name, contact info, and a GitHub/portfolio link; recruiters check these before reading further.
2. **Summary** — 2-3 lines naming your stack and focus area, so a skimming reader immediately knows where you fit.
3. **Skills** — languages, frameworks, and tools grouped into categories so a recruiter can scan for keyword matches in seconds.
4. **Experience** — reverse-chronological, outcomes-first; this section carries the most weight in any screen.
5. **Projects** — 1-2 notable projects, especially useful if your work experience is limited or doesn't show the stack you're targeting.
6. **Education** — degree, institution, and graduation year; keep it brief once you have real work experience.

## Key Competency Areas

- Designing and implementing features end-to-end, from requirements to deployed code
- Writing maintainable, well-tested code that other engineers can build on
- Debugging and resolving issues in production systems under time pressure
- Collaborating with other engineers through code review and technical discussion
- Making sound technical tradeoffs under real constraints — time, scale, and legacy code
- Communicating technical decisions clearly to both engineers and non-engineers
- Picking up new languages, frameworks, or parts of a codebase quickly
- Estimating your own work reasonably and flagging risk before deadlines slip

## Bullet Point Framework

Structure each bullet as **action + scope (what system, how big) + measurable impact** (performance, reliability, adoption, or business metric). Avoid bullets that only describe a task — always close the loop with what changed as a result.

- Built [feature/service] using [stack], reducing [page load time / API latency] by [X%]
- Refactored [system] to [new approach or pattern], cutting [build time / error rate] by [X%]
- Diagnosed and fixed [production issue] affecting [N users/requests], reducing recurrence by [X%] over [timeframe]
- Shipped [feature] end-to-end from design through deployment, adopted by [N] users or teams within [timeframe]
- Improved automated test coverage for [module] from [X%] to [Y%], cutting regression bugs by [Z%]
- Optimized [slow query/process], reducing runtime from [X seconds] to [Y seconds]

## Tips for Software Engineer Resumes

- Lead bullets with the outcome or problem solved, not just the technology used to solve it.
- Quantify wherever possible — latency, error rate, load handled, adoption, or time saved.
- List only languages and tools you can speak to confidently in a technical interview.
- If your work experience is thin, strong side projects with real usage or complexity can carry real weight — always link to the code.
- Keep the resume to one page unless you have 8+ years of experience.
- Tailor the Skills section per application — mirror the language the job posting uses where it's honest to do so.
- Order your Experience bullets by impact, not chronology within a role — put your strongest result first.
