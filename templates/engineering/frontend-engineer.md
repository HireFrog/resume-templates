# Frontend Engineer Resume Template

> **Format:** Markdown (`.md`) · **Designed for:** Humans + AI agents

*For engineers focused on building user-facing interfaces, web performance, and client-side architecture.*

Frontend hiring managers screen for a mix of UI craftsmanship, performance awareness, and collaboration with design and product. This template emphasizes what you shipped, how it performed for real users, and how closely you worked with design — since frontend work is one of the few disciplines where a reviewer can actually click through and see your output. Link to live work wherever you can.

## Resume Structure

1. **Header** — name, location, email, GitHub/portfolio, LinkedIn.
2. **Summary** — 2-3 lines on your frontend focus (web, mobile web, design systems) and stack.
3. **Skills** — languages, frameworks, and styling/tooling, grouped for scanability.
4. **Experience** — reverse-chronological, with UI, performance, and adoption-driven bullets.
5. **Projects** (especially valuable early-career) — with live links where possible so reviewers can interact with the work.
6. **Certifications** (optional) — rarely required for frontend roles; include only if directly relevant (e.g. accessibility).
7. **Education** — degree, institution, year.

## Key Competency Areas

- Building responsive, accessible user interfaces that work across devices
- Component architecture and design systems that other teams can reuse
- Web performance: load time, rendering strategy, and bundle size
- State management and client-side data flow in nontrivial applications
- Cross-browser and cross-device compatibility
- Collaboration with design and product on UX decisions, not just implementation
- Testing UI code (unit, integration, visual regression)
- Debugging issues that only reproduce on specific browsers, devices, or network conditions

## Bullet Point Framework

Use **action + UI or system built + user or performance impact**. Describe what you built and quantify performance, adoption, or conversion impact — frontend work has some of the most measurable user-facing metrics available, so use them.

- Rebuilt [the checkout flow] in [React], improving conversion by [4%] and reducing page load time by [1.2s]
- Built [a component library] adopted across [5] product teams, cutting UI development time by [30%]
- Improved Lighthouse performance score from [62] to [94] by optimizing [bundle size and image loading]
- Implemented [accessibility improvements] achieving [WCAG 2.1 AA] compliance across [the core app]
- Led migration from [older framework] to [React/Vue], reducing bundle size by [35%]
- Partnered with design to ship [a redesigned dashboard] used by [50K daily active users]

## Tips for Frontend Engineer Resumes

- Include performance metrics (load time, Lighthouse score, bundle size) — they're concrete and hiring managers look for them specifically.
- Link to live work whenever possible; frontend is one of the few disciplines where hiring managers will actually click through.
- Call out accessibility work explicitly — it's increasingly a differentiator and a compliance requirement for many teams.
- Show collaboration with design: mention working directly from Figma, contributing to a design system, or shaping UX decisions.
- Name specific frameworks and versions rather than "modern JavaScript frameworks" — recruiters and ATS filters look for exact matches.
- If you've worked in a monorepo or with a shared design system, mention the scale (number of consuming teams/apps) — it signals reuse impact.
- Note any experience with animation, responsive design, or internationalization if the role calls for it — these are common gaps reviewers screen for.
